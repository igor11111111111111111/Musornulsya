# Мусорнулся — структура проекта

Викторина по УК РФ. Ведущий объясняет статью **голосом в Discord**, игроки пишут
номер статьи и часть в приложении. Баллы ставит ведущий вручную — автопроверки нет.

## Первый запуск

1. **Photon App ID.** `Tools > Fusion > Fusion Hub`, вставить App ID типа **Fusion**
   с [dashboard.photonengine.com](https://dashboard.photonengine.com).
   Без него игра не стартует и покажет об этом сообщение в лобби.
2. **Собрать сцены.** Меню `Musornulsya > Собрать сцены`.
   Создаст `Scenes/Lobby.unity`, `Scenes/Game.unity`, префабы в `Prefabs/`
   и пропишет обе сцены в Build Settings.
3. **Проверить префабы.** Открыть `Prefabs/GameRoom.prefab` и убедиться, что
   поле `Player State Prefab` заполнено. То же для `RoomConnector` в сцене Lobby —
   поле `Game Room Prefab`. Если пусто, назначить вручную (см. ниже про NetworkPrefabRef).
4. **Зарегистрировать сетевые префабы.** Fusion должен знать о `GameRoom` и `PlayerState`.
   Обычно подхватывает автоматически при импорте; если нет —
   `Tools > Fusion > Rebuild Object Table`.
5. Запустить сцену `Lobby`.

## Проверка вдвоём

Photon Free даёт 20 CCU, для теста хватает. Варианты:
- Editor + собранный билд на той же машине
- Multiplayer Play Mode (`Window > Multiplayer > Multiplayer Play Mode`)

Один нажимает «Создать игру» и диктует код, второй вводит код и жмёт «Присоединиться».

```

    ArticleData.cs        Модели JSON + ArticleRef (статья с конкретной частью)
    ArticleDatabase.cs    Загрузка Resources/uk_rf.json, случайная выдача без повторов
  Core/

    AnswerHint.cs           Подсветка совпадений для ведущего (НЕ автопроверка)
  Network/
    PlayerState.cs        Имя, ответ, очки, флаг подключения. Один на игрока
    GameRoom.cs           Фазы раунда, роль ведущего, переподключение

  UI/
    LobbyUI.cs            Экран входа
    GameUI.cs             Главный экран: панель ведущего или панель игрока

```

## Как устроена роль ведущего

Различаются две вещи:

- **`HostPersistentId`** — кто ведущий «по жизни». При отвале **не меняется**,
  ждёт возвращения.
- **`CurrentHostRef`** — кто исполняет обязанности прямо сейчас.

Ведущий отвалился → обязанности переходят старейшему по `JoinOrder`.
Ведущий вернулся → `RPC_RequestJoin` видит совпадение `PersistentId` и возвращает роль.

Очки переживают отвал: `PlayerState` спавнит **ведущий**, а не сам игрок,
поэтому Fusion не удаляет объект при выходе владельца. Отключённый игрок
остаётся в таблице серым, при возврате подхватывает свой `PlayerState` с очками.

Если из комнаты вышли **все** — сессия Photon умирает вместе с состоянием.
Это осознанное ограничение: без внешнего хранилища не восстановить.

## Про NetworkPrefabRef

`SceneBuilder` пытается записать ссылки на сетевые префабы автоматически, но
внутреннее поле `NetworkPrefabRef` меняется между версиями Fusion. Если в консоли
появилось предупреждение «Не удалось записать ссылку на префаб» — назначь префаб
в инспекторе руками, это одно поле.

## Расширение базы статей

`Resources/uk_rf.json`. Обёртка `{"articles": [...]}` обязательна —
`JsonUtility` не умеет корневой массив и молча вернёт `null`.

Формулировки в текущем файле написаны по памяти и **не сверены с действующей
редакцией**. Перед расширением до сотни статей стоит сверить с
[pravo.gov.ru](http://pravo.gov.ru) или КонсультантПлюс.

Для игры интересна Особенная часть (ст. 105–361). Общая часть (1–104) —
определения и порядок назначения наказания, для викторины мёртвый груз.

## WebGL

- Fusion работает через WebSocket-транспорт, отдельной настройки в коде не требует.
- `PlayerPrefs` в браузере — IndexedDB. Переживает перезагрузку вкладки,
  но **не работает в приватном окне**: там игрок каждый раз новый, с нулём очков.
- В Player Settings проверить Compression Format (Gzip/Brotli) и настройки сервера.
